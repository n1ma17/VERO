# Remember

Long-term memory for the agent. Read at the start of every task, update at the end.

## User preferences
- The user may write in Persian (Finglish) in chat; **app UI stays English**. Reply in the user's language; code, comments, and memory files stay in English.
- Strict component-based architecture: no logic in pages, every component owns its logic.
- Every page has a matching folder in `components/` with the same name.
- Tailwind for all styling; all colors from `src/styles/theme.css`.
- Agent must use the `.agent/` memory (architect / remember / review) instead of re-reading everything.

## Decisions
- Visual direction ("must not look AI-made"): exactly 3 colors, 60% `#19191B` background, 30% `#8C8E92` text, 10% `#FF5410` used only for the one primary button and tiny details (overdue labels, small square marks, an active-tab tick, the current-month chart cap). No gradients, glass, emojis, sparkles, or soft shadows. One bold display font (Archivo, big, tight, left-aligned) plus one plain font (IBM Plex Sans). Lay everything out on a 12-column grid. Separate content with hairline rules (`border-text/20`), not filled cards. Show the real product large. Use opacity of `text` only for hairlines and muted chart bars, never as a fill tint.
- Tailwind v4 CSS-first config: theme is defined with `@theme` in `theme.css`; there is no `tailwind.config.js`.
- `--color-*: initial` in `theme.css` removes the default palette so only theme colors can be used.
- Page files are named `<Name>Page.vue`; their component folder is `components/<Name>/` (without the `Page` suffix).
- Shared reactive state lives in composables as module-level refs (simple singleton store). No Pinia yet — add it only if state grows complex.
- Money data lives in Postgres `app_money` via Nest. Vue composables load bills, deposits, expenses, installments, and companies from their own GET endpoints (not `GET /api/wallet`). View-month keys stay in `localStorage`. `PUT /api/wallet` is only for Excel import (includes optional `companies`).
- Bill logos are company logos: define companies (name + image), pick on the bill form, or leave Others. Cards show the selected company image via `logoKey` (= company id when it has a logo). Company names are unique per user (case-insensitive); new users have no companies until they add them.
- Canonical dates in Postgres and the Nest API are Gregorian `DATE` / ISO `YYYY-MM-DD`. The Vue UI calendar follows display currency: **IRR → Jalali**, **USD/EUR/GBP → Gregorian** (`utils/calendar.ts` + `moneyApi.ts`). Field names like `jalaliYear` still mean “UI calendar date”.
- Transactions statement: IRR uses Jalali views; other currencies use Gregorian views (`008_gregorian_ledger.sql`). `GET /api/ledger?date=` is day 1 of the viewed calendar month as ISO. Dashboard charts use the collection cache in the active calendar.
- Bill duration stays a 1–60 slider in the UI. On save it becomes `startOn`/`endOn` ISO (`billEndIso`). Bills and expenses pages both have a Jalali month navigator; new rows default to the viewed month.
- Auth is Better Auth (email/password, httpOnly session cookie). Login/register UI is still an admission ticket; success stamps the stub then redirects; failure stamps REJECTED and shows Try again. Passwords hashed by Better Auth in `accounts.password`. Forgot password uses existing `sendResetPassword`: generate a temp password, email it, then `hashPassword` into `accounts`. SMTP via nodemailer when `EMAIL_PROVIDER=smtp`.
- User service follows the vin project: `UsersModule` + `PgService`, public columns only, `role` is `ADMIN` | `USER` (not vin's `PRINCIPLE`). Role/status are not client-writable.
- Nest Better Auth must construct `kyselyAdapter` with `usePlural: true` (tables are `users`/`sessions`/`accounts`/`verifications`). `bodyParser: false` in `main.ts`.
- Arcjet is global Shield + 120 req/min. Local `ARCJET_MODE=DRY_RUN`. Logo uploads reject SVG at the API.
- Installment status is never stored: `overdue` is derived from `dueDate` + `paidAt`. Only `paidAt` is persisted.
- Installments list is read-only; status is changed only on the detail page (user requirement).
- Paying happens through the receipt printer on the detail page: the printer prints first, then the installment is marked paid and the left card updates.
- When porting React/HTML+CSS the user provides: Vue primitives + `theme.css` tokens; complex 3D/::before chrome goes in `main.css` `@layer components` (same pattern as bank card / bottom nav). Receipt printer is the ICprint thermal body; print still follows `idle → processing → printing → complete` (not click-to-toggle).
- Receipt look: white card, colored status strip on top, notched dashed dividers, scalloped bottom, monospace values, "APPROVED" stamp on paid ones. Keep the stamp off data rows (on detail it has its own row).
- Receipt printer (user reference image, 2026-11-18): slim dark printer bar on top (hairline border, status text and LED along the top, slot line along the bottom). Paper feeds **down** out of the slot at every width, because the printer always sits at the top of its column (user request; upward feed was tried and rejected). Paper has zigzag top and bottom edges. On `complete` the receipt tears off (`is-out`: moves 1rem away from the slot and tilts 2deg) and a zigzag stub shows in the slot. Auth (`pin-slot`) never tears, because it's an interactive form. Printed receipts use shared `ReceiptPaperHeader` (logo, spaced MONEY, kind, meta) and `ReceiptPaperFooter` (status + ref, barcode, note).

- Ledger balance = all deposits (by counted month) minus **paid** bill installments (by payment month in Asia/Tehran) minus all expenses (by purchase month); cumulative, can be negative. Unpaid installments do not affect balance until paid.
- Postgres lives in repo `database/` and local database `app_money` (PostgreSQL 18, port 5432, user `postgres`). Cluster files stay in `F:\database`. Money rows are per `user_id`. Installments and the ledger are views; only `paid_at` is stored. SQL `date_to_jalali` matches `jalaali-js` 2.0.1. Overdue uses `Asia/Tehran`. Identity is Better Auth (`004_better_auth.sql`). Existing DBs migrate via `002a_gregorian_dates.sql` (`npm run db:migrate`).
- Deposits wallet (user request, 2026-11-18) is an intentional exception to the 3-color/4px rules: pastel card fills and ~14–20px radii (`rounded-[0.875rem]` / `rounded-[1.25rem]`). The folder stays straight, not tilted like the reference image.
- Color language: deposits = success (green), bills = danger (red), expenses = warning (amber).
- Printer pages share `createPrinterFlow` (`usePrinterFlow.ts`); editing reuses the entry page with an optional `:id` route param.
- Receipt paper feed/retract is a CSS `transform` **transition** (2s out, 1.4s in), not keyframes. Keyframe `from` on class swap made the sheet peek, snap back to `-110%`, then feed. Auth print waits for a painted hidden frame (double rAF, 48ms timeout fallback).
- Charts are hand-written SVG with `fill-*`/`stroke-*` theme classes; no chart library. Dynamic sizes go in SVG attributes, never inline `style`.
- Multi-currency (user answers 2026-11-21): rows keep the amount + currency they were entered in forever; everything is converted at **today's live rate** (past figures move with the market); USD/EUR/GBP from a public API, IRR free-market rate entered manually per user (`users.irr_per_usd`, falls back to official API rate); Toman dropped (data ×10 → IRR); selector is a navbar menu with code badge. Sums are normalized to USD in SQL, converted once in the API; the client converts unrounded and rounds only in `formatMoney`.
- GitHub remote is `https://github.com/n1ma17/VERO.git` on `master`. The Vue app used to sit at the VERO root; it now lives under `front-end/` with `back-end/` and `database/` beside it.

## Gotchas
- Nest feature modules must appear in `AppModule.imports`, not only a top-level `import` line — `CompaniesModule` was imported in `app.module.ts` but omitted from `imports`, so `/api/companies` 404’d and post-login `loadMoneyCollections()` failed.
- Nest Observe (`@nestjs/observe`) with `YOUR_APP_KEY` / `YOUR_APP_SECRET` hits observe.nestjs.com and logs `Telemetry rate-limited (429)` about every flush; it pauses sends for 60m but does not by itself exit Nest. Leave `OBSERVE_*` unset locally; enable only with real keys from observe.nestjs.com. Separate crash risk: Arcjet HTTP/2 unhandled timeout (see review.md).
- Bottom nav: never put `env(safe-area-inset-bottom)` as padding/margin on the *dock* outside the bar — on gesture-nav phones that leaves a empty gap above the home indicator. Put the inset as `padding-bottom` *inside* `.app-bottom-nav` so the bar fill reaches the screen edge, and keep the icon row at a fixed `5rem` with `align-items: flex-start` (not `center`, or icons float in the padded height).
- APK API URL: do not `import @capacitor/core` in `apiBase.ts` — Rollup folds `isNativePlatform()` to `false` and strips `VITE_API_URL`; native builds call `http://<host>/api` (no :3000), auth fails, bottom nav hidden (`!isAuthenticated`). Use `globalThis.Capacitor` + call `apiBaseUrl()` per request (not module init).
- Capacitor launcher icon is **not** `cap sync`. Only change `src/assets/icon.png`, then `npm run assets:android` (`icons:sync` copies to `public/` + `assets/`, deletes stale `assets/icon-only.png` which overrides new `icon.png`). Rebuild APK; Android Studio **Build → Clean Project**. On Windows npm, do not wrap hex colors in single quotes (`'#19191B'` breaks `@capacitor/assets`).
- Capacitor Android black screen: default `https://localhost` blocks HTTP API (mixed content); `getSession` throw left the loading overlay stuck on `#19191B`. Fix: `server.androidScheme: 'http'`, hostname from `VITE_API_URL`, `CapacitorHttp`, catch in `ensureAuthReady`, end loading in `beforeEach` finally. Nest `AUTH_TRUSTED_ORIGINS` must include `http://localhost` and `http://<LAN-IP>`; Nest listens on `0.0.0.0`. Phone and PC must be on the same Wi‑Fi; Windows Firewall must allow port 3000.
- Deposit pocket follows the user's sleeve image (sampled pixel colors in `theme.css`): cards `h-52` fan above the pocket with a 3.75rem peek and slight tilt (`-4deg`, `1.5deg`, `0`); dark back starts at the front card's top; SVG front with a shallow dip + dashed stitch; centered total, "Total Balance", green eye. Item and `__body` margin-top must equal -(card height − peek) = `-9.25rem`. Hero `BankCardPlastic` stays separate.
- When the user gives a reference image, sample it (Pillow is installed: `python -c "from PIL import Image..."`) and copy measured colors, proportions, and edges instead of guessing.
- Vite may bind to **5174** when **5173** is busy; `AUTH_TRUSTED_ORIGINS` must include that origin or the browser shows CORS / Better Auth `INVALID_ORIGIN` (curl without `Origin` can look fine).
- Browser + `VITE_API_URL=http://192.168.x.x:3000` breaks auth: sign-in returns 200/`Set-Cookie`, but later `/api/*` are 401 because `localhost`→LAN is cross-site and `SameSite=Lax` cookies are not sent. Fix: browser uses relative `/api` (Vite proxy); only Capacitor native uses the LAN absolute URL. Keep `VITE_API_URL` as the phone LAN for `cap sync`; do not point the browser at the LAN host.
- Tailwind cannot see dynamically built class names; use lookup objects with full class strings.
- `shadow-lg` etc. no longer blur: theme redefines them as 1px hairline rings, so cards get an outline for free. Do not add arbitrary `shadow-[...]` values or `blur-*`, because the blur scale is cleared and blurred blobs render as hard circles.
- `success`/`warning` are now the same gray as `text`. Deposits, bills, and expenses are told apart by labels and +/− signs, not color; only `danger` (overdue/negative) is orange.
- In Postgres, `offset` is reserved. Do not use it as a `generate_series` column alias.
- On this PC, `bash` launched from Windows Python is WSL and does not start. Apply SQL with `psql.exe`, Git Bash via `database/scripts/apply.sh`, or `npm run db:migrate` from `back-end/`.
- `@arcjet/nest` 1.14 peer range is Nest 10/11; this repo uses Nest 12 with `legacy-peer-deps=true` (same as vin).
- `bg-white`, `text-black`, `bg-gray-*` etc. do not exist (palette disabled). Use `bg-surface`, `text-content`, ...
- Nested `.git` folders in `front-end/` or `back-end/` make the root repo skip those trees. Keep a single `.git` at the repo root.
- `001_calendar.sql` is already applied on the live local DB, so `date_to_jalali` helpers also live in `002a_gregorian_dates.sql`. Fresh installs get them from 001; 002a is idempotent.
- Installment ids are `billId__YYYY-MM-DD` (Gregorian due date). Old `billId__YYYY-MM` URLs break after the date migration.
- `pg` DATE values must use local `getFullYear`/`getMonth`/`getDate` in `toDateOnly` — UTC `toISOString().slice(0,10)` is a Tehran off-by-one.
- Paper is `#8C8E92`, the same color as `text`. Anything inside `.receipt-printer-sheet` gets ink tokens re-scoped in CSS. Content rendered on paper outside the sheet still needs explicit `text-on-paper`.
- Do not animate `.receipt-printer-sheet` with `@keyframes` on `transform`. Swapping `is-hidden` → `is-printing` flashes a frame (paper peeks, retracts, then feeds). Transition from the current `translateY(-110%)` instead. Start auth at `idle` so the hidden frame paints before `printing`.
- Changing a column type used by a view fails in Postgres: drop `v_ledger_entries`, `v_month_totals`, `v_installments` first, then recreate (latest definitions in `007_multi_currency.sql`).
- FX providers take ~9s from this network via Node `fetch` (curl ~4s); `open.er-api.com` sometimes fails inside Nest ("fetch failed") while the jsDelivr fallback works. Keep timeouts ≥ 20s and never block requests on refresh once real rates exist.
- Display-converted store lists are new objects on every recompute; form watchers must key on the row id (`editingDeposit.value?.id`), not the object, or a currency change wipes in-progress edits.
- Seeded admin email is `nimaab1992@gmail.com` (not `nima1992@gmail`). Forgot password with `EMAIL_PROVIDER=log` writes the new password only to the Nest console. Restore the `.env` password with `npm run db:reset-admin-password` from `back-end/` — do not re-run `db:seed` just to fix a password (that re-imports the Excel wallet).

- Navbar popovers on mobile (below `sm`, `matchMedia('(max-width: 39.999rem)')`) become bottom sheets: `<Teleport to="body" :disabled="!isMobile">`, `z-[150]` sheet + `z-[140]` backdrop (above bottom nav 50 and loading 100, below datepicker 200 / toasts 300), lock body with `overflow-hidden`, pad `env(safe-area-inset-bottom)`. Inputs inside use `text-base` on mobile so iOS does not zoom.
